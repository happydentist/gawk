# Source-Level Security Audit — vendored gawk @ 5.4.1

This audit reviews `upstream/gawk/` in the ljh-sh/gawk repository as
shipped in v5.4.1. The audited tree is byte-for-byte identical to
upstream GNU Awk 5.4.1 (released 2026-04-30 by the FSF gawk team) —
**no local patches applied**.

The audit was conducted by reading the C source under
`upstream/gawk/*.c`, `upstream/gawk/extension/*.c`, and the supporting
header files. No fuzzing, no coverage instrumentation, no formal
verification. The 5.4.1 codebase is ~55k LOC across .c/.h, a mature
codebase with ~20+ years of production hardening by the FSF.

## Distribution model (ljh-sh/gawk bundled-shared)

This release uses the **bundled-shared** model (per
`bundled-build.rule.yml`):

```
bin/gawk              ← single CLI, RPATH='$ORIGIN/../lib' (Linux)
lib/libgmp.so.*       ← bundled from system
lib/libmpfr.so.*
lib/libreadline.so.*
lib/extension/*.so    ← gawk loadable extensions
```

All upstream features are ENABLED: `--enable-shared
--enable-extensions --with-readline --with-mpfr --enable-pma`. The
build does NOT patch upstream gawk; it only changes configure flags
and bundles the runtime deps into `lib/`.

## Threat model context

`gawk` is a **script interpreter**. Its primary job is to execute
user-provided AWK programs — so by design, any AWK script is
attacker-controlled code running inside the gawk process with the
caller's UID. The trust boundary is NOT "gawk filters AWK input";
it's "the operator trusts the AWK program enough to run it as their
own user".

Given that, this audit focuses on:

| # | Threat | Where it could go wrong |
|---|--------|--------------------------|
| A | **AWK-script source loading** (`-f file`, `@include file`, `-l lib`) | Path traversal; library loading from untrusted AWKLIBPATH |
| B | **Sub-process invocation** (`system()`, `print "cmd" | "cmd"`, `getline "cmd"`) | Command injection via shell metacharacters |
| C | **Network I/O** (`/inet/...`) | SSRF via user-supplied URLs |
| D | **Persistent memory allocator** (PMA backing files) | File corruption / unintended file overwrite (opt-in via env var) |
| E | **Dynamic extensions** (loadable .so via `-l` / `@load`) | dlopen from untrusted AWKLIBPATH — **mitigated by RPATH** in this build |
| F | **Locale / environment handling** | Locale-dependent parsing bugs |
| G | **Filesystem redirection** (`> file`, `>> file`, `| cmd`) | Overwrite sensitive files |
| H | **Bundled .so supply chain** (new in bundled-shared mode) | .so files not signed; integrity relies on git subtree vendor lock |

## Severity scale

| Level | Meaning |
|-------|---------|
| **HIGH** | Reachable by attacker-controlled input, real impact (file overwrite, code execution, privilege escalation) |
| **MEDIUM** | Reachable, but harder to trigger or limited impact (DoS, partial corruption) |
| **LOW** | Reachable in narrow scenarios, or low impact (decoder corruption, edge case) |
| **INFO** | Not a bug, recorded for posterity |

## Detailed findings

### #1 (HIGH) — `@include` / `-f` resolves via `AWKPATH` with no containment check

**Where**

- `io.c:3046` `do_find_source` — searches `AWKPATH` (colon-separated
  directory list) for the file, then concatenates `pi->awkpath[i] +
  src` and `stat()`s the result.
- `main.c:894` `path_environ("AWKPATH", defpath)` — installs the
  default `AWKPATH` if env var absent.
- `main.c:956` `putenv(AWKPATH)` / `putenv(AWKLIBPATH)` — env vars
  preserved across `system()` calls.

**Effect**

If an attacker can set the operator's `AWKPATH` env var (e.g. via a
shell init file in a multi-tenant context), a `gawk -f foo` invocation
that should fail instead loads `/attacker/path/foo` as the AWK
program — full code execution as the operator.

**Mitigation in this distribution**

- No build-time fix possible (env var is operator-controlled).
- Pages `security.html` will warn operators to unset `AWKPATH` /
  `AWKLIBPATH` before running untrusted scripts.
- The shim approach (`bin/gawk` shim execs real binary) — RPATH
  does NOT affect AWKPATH behavior; the shim does not sanitize
  AWKPATH either.

### #2 (MEDIUM) — `@load` / `-l` accepts arbitrary `dlopen()` path — RPATH-mitigated

**Where**

- `ext.c:109` `if ((dl = dlopen(lib_name, flags)) == NULL)`
- `io.c:3117` `sprintf(file_ext, "%s%s", src, EXTLIB_SUFFIX)` —
  constructs the `.so` filename from AWKLIBPATH.
- `configure.ac:337–370` extension detection logic.

**Effect**

Without RPATH, an attacker who can set `AWKLIBPATH` (or who can
place a `.so` file in any of the default library paths) can have
gawk `dlopen()` an arbitrary binary, which then runs as the
operator's UID with full control.

**Mitigation in this distribution**

- RPATH='$ORIGIN/../lib' (Linux) / @loader_path/../lib (macOS)
  embeds the `.so` search path at build time. **The runtime linker
  searches the RPATH path FIRST** before any env var or system path.
- Even if AWKLIBPATH is set, the dlopen result must match a `.so` in
  our bundled `lib/extension/` (or fail).
- Side benefit: the dlopen search path is now documented in the
  binary itself (`readelf -d bin/gawk | grep RPATH`).

**Why MEDIUM, not HIGH**

- Operators who set `LD_LIBRARY_PATH` (Linux) or
  `DYLD_LIBRARY_PATH` (macOS) before invoking the shim can still
  shadow our bundled `.so` — glibc's runtime linker checks
  LD_LIBRARY_PATH AFTER RPATH, so our bundled .so wins on
  modern glibc (≥ 2.36). But older glibc versions may behave
  differently.
- The `.so` files themselves are not signed (see #8).

### #3 (MEDIUM) — `system()` / pipe I/O use fixed `/bin/sh -c`

**Where**

- `io.c:2083` `execl("/bin/sh", "sh", "-c", command, NULL);`
- `io.c:2135` `execl("/bin/sh", "sh", "-c", command, NULL);`

**Effect**

This is actually a **good** finding (counterintuitively labeled
MEDIUM for documentation). Gawk uses an absolute path `/bin/sh`,
which closes the classic `PATH`-lookup hijack that plagues
`system(3)` in user-space C programs.

The MEDIUM rating reflects that AWK scripts can still invoke arbitrary
shell commands — but that's an **AWK language feature**, not a gawk
vulnerability. Operators running untrusted AWK scripts must understand
that `system("rm -rf $HOME")` will execute.

### #4 (MEDIUM) — PMA backing file overwrites without confirmation

**Where**

- `main.c:1927` `persist_file = getenv("GAWK_PERSIST_FILE")`
- `support/pma.c` — persistent malloc with backing mmap'd file

**Effect**

If an operator sets `GAWK_PERSIST_FILE=/some/path`, gawk mmaps that
file as its heap. If the file exists and is smaller than expected,
gawk extends it; if larger, gawk truncates. A typo or misconfigured
env var can silently overwrite a meaningful file.

**Mitigation in this distribution**

- This build ENABLES PMA (user requirement: full gawk features).
- `smoke.sh` does NOT exercise PMA — focuses on basic interpreter.
- Pages `security.html` will note that PMA is opt-in and requires
  intentional env var setup.

### #5 (MEDIUM) — `/inet/` redirect URL handling

**Where**

- `io.c` `/inet/` redirect handling — uses `getaddrinfo()` /
  `socket()` / `connect()` to open arbitrary URLs from AWK programs.
- Documented as a `gawk` extension; POSIX awk doesn't have this.

**Effect**

AWK scripts that take URL input from untrusted sources can trigger
SSRF against internal services.

**Mitigation**

- Pages `security.html` will note that operators running AWK scripts
  handling network input are responsible for input validation.

### #6 (LOW) — Environment variable precedence

**Where**

- `main.c:248` `getenv("GAWK_LOCALE_DIR")`
- `main.c:296` `getenv("GAWK_GNU_MATCHERS")`
- `main.c:323` `getenv("POSIXLY_CORRECT")`
- `main.c:951` restore env for system() calls

**Effect**

Multiple env vars are honored for behavior switches. Most are
benign.

**Mitigation**

- Pages `security.html` will warn: gawk is NOT setuid-safe.

### #7 (LOW) — `/dev/...` writes honored verbatim

Standard Unix behavior. Pages will note that gawk honors the OS file
model.

### #8 (LOW) — Bundled `.so` files not signed

**Where**

- `lib/libgmp.so.*`, `lib/libmpfr.so.*`, `lib/libreadline.so.*`,
  `lib/libhistory.so.*`, `lib/libncurses.so.*`, `lib/extension/*.so`.

**Effect**

The bundled `.so` files are copied from system packages (apt/brew/MSYS2)
without signature verification. An attacker who compromises the
build pipeline can replace `.so` files in the archive, and end-users
have no way to detect it (short of manually diffing against upstream
package hashes).

**Mitigation**

- Vendor integrity: `upstream/gawk/` is locked via git subtree;
  build is reproducible from a known CI commit.
- RPATH: `.so` search path is locked to our bundled lib/, so a
  compromised archive cannot load `.so` from arbitrary paths.
- Future: cosign/sigstore signing of release archives (deferred to
  a later ljh-sh release — see `feedback-eget-verifies-checksums`).

### #9 (INFO) — glibc version binding

The Linux glibc build is done on `ubuntu-24.04` (glibc 2.39).
The resulting binary requires glibc ≥ 2.39 at runtime. Older Linux
distros (Debian 11, RHEL 8) will fail with "version `GLIBC_2.39' not
found".

**Mitigation**

- Pages `install.md` will document the minimum glibc.
- Future: build on older glibc base (e.g. ubuntu-22.04 = glibc 2.35)
  to widen compatibility — deferred.

### #10 (INFO) — MinRX is the new default regex engine

**Where**

- `NEWS 5.4.0 §1` "This release now uses Mike Haertel's MinRX regular
  expression matcher as the default regexp engine."

POSIX awk scripts with ReDoS-prone patterns (e.g. `^(a+)+$`) are
mitigated by MinRX's algorithmic complexity guarantees. Positive
security change.

### #11 (INFO) — LLM-generated contributions explicitly rejected

**Where**

- `NEWS 5.4.1 §10` — "The manual now states that contributions of
  code created by LLMs won't be accepted."

A positive supply-chain signal.

## Conclusion

**Headline:** gawk 5.4.1 is a mature, well-audited codebase.
Compared to the strict-static distribution model, the bundled-shared
model has different trade-offs:

| Aspect | strict-static | bundled-shared (this) |
|--------|---------------|----------------------|
| Binary size | ~3 MB (all-in-one) | ~1 MB (bin/) + ~10 MB lib/ |
| Feature coverage | Disabled: readline, mpfr, extensions, pma | **All enabled** |
| `dlopen` attack surface | Closed (no extension support) | Mitigated by RPATH |
| `.so` supply chain | N/A (no .so) | .so not signed; integrity via git subtree |
| Libc binding | musl-static (universal) | glibc ≥ build-host (Ubuntu 24.04 = 2.39) |
| `awk` alias | User creates symlink at deploy | User creates symlink at deploy |

The single remaining HIGH is **#1** (`AWKPATH` path traversal) — this
is an AWK language feature, not a gawk vulnerability, and has no
build-time fix.

The MEDIUM findings are documented AWK language features; the static
build does not change them.

**Recommended deployment posture for ljh-sh/gawk:**

1. Bundle all upstream features — user requires full gawk.
2. RPATH='$ORIGIN/../lib' provides portable lib lookup (Linux/macOS);
   Windows uses application-local DLL search.
3. Operate AWK scripts in a controlled environment with sanitized
   `AWKPATH` / `AWKLIBPATH` / `GAWK_*` env vars.
4. Do not invoke gawk with setuid / sudo / as a privileged service
   binary.
5. Treat AWK script source files as code (review them, don't pass
   untrusted .awk files via `-f`).
